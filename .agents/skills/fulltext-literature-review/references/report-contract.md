# Basic delivery contract

## Three completion criteria

1. Reading: all supplied text and images have actual observations. Report missing/unread units explicitly.
2. Reports: every planned paper has current JSON and readable Markdown; synthesis.md answers the question and accounts for all papers. Empty placeholders do not count.
3. Core findings: independent basic checks have returned for papers and synthesis. Definite conclusions are supported; errors are corrected or visibly qualified as unresolved. Missing checks cannot be disguised as uncertainty alone.

When these hold, deliver as complete, adding known limitations where needed. Otherwise deliver existing reports as partial, naming the missing work. An unanswered research question may be an honest finding when evidence is insufficient; dropping all content to obtain a pass is not completion.

## Ownership and evidence

Readers own paper JSON; different checkers own check JSON. Coordinator owns sources.json, run.md and synthesis.md. Generated paper Markdown comes from JSON. Preserve raw inputs and historical runs.

Keep source IDs, original text ranges or figure regions beside key findings. Numbers retain metric, comparator, dataset and evaluation conditions. Distinguish author findings from interpretation. A source mismatch or content change invalidates affected support; it does not prevent writing other reports. Actual independent inspection is required: copying evidence is not a check.

## Bounded correction

One consolidated content repair per paper and one targeted confirmation by its original checker. Unclear remaining findings become explicit limitations, never automatic support. Formatting cleanup does not consume this content repair. Tools supply hashes and omit inapplicable fields; they cannot invent evidence or repair scientific meaning.

Save the original report before content repair. Retain support only when the corresponding content and sources have not changed. Missing old dispatch events stay unknown; do not backdate them.

## Reporting

Every reader output is initially unverified. Update visible status after checking. Report text must visibly identify pending points; technical logs belong in run.md.

No elaborate dispatch event sequence is required for new runs. Record available start/first-report/delivery times, basic acceptance and repair counts. Tools validate structure and file consistency; they do not prove comprehension or scientific correctness.
