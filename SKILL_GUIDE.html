全文閱讀，集中抓重點，交付綜合報告

Skill：fulltext-literature-review。2026-10-27 精簡改版。輸入本機 Markdown 論文及圖片；完整閱讀，通常每篇整理 3–5 個核心發現，做一次獨立基本查核。

使用方式

提供論文資料夾、研究問題和輸出位置即可。有既定焦點直接沿用；沒有時先採明示的描述性概覽。輸出依使用者語言，未指定則英文。十分鐘不是硬期限。

使用 fulltext-literature-review 閱讀 test_papers_3，
比較三篇方法、主要證據與限制。集中抓重點，產生每篇報告與 synthesis.md。

五步流程

  1. 登錄來源，每篇 reader 完整閱讀文字及圖片。
  2. 寫精簡 JSON，立即產生單篇 Markdown。
  3. 另一位 checker 核對主結論、關鍵數字及重要限制。
  4. 有問題才集中修正一次，原 checker 只確認修改與受影響結論。
  5. 完成綜合報告，由一位 checker 簡短檢查跨篇推論後交付。

最多十個同時工作的 subagents。三篇測試使用三位 reader 和三位 checker，綜合查核沿用其中一位。剩餘疑點明示，不重啟整批閱讀。

產物

檔案內容
papers/P001.json問題、方法、核心發現、來源定位、限制及閱讀紀錄；工具補入來源資訊。
papers/P001.md簡潔可讀的單篇報告，不逐欄展開機器資料。
checks/P001.json獨立基本查核的支持／需修正／待確認判定及短理由。
synthesis.md主交付：回答研究問題、比較表、共通點與差異、限制、單篇連結。
checks/synthesis.json簡短的綜合查核。
run.md時間、基本驗收及執行診斷；與文獻內容分開。

驗收只有三項

  1. 所有供應文字及圖片已實際閱讀。
  2. 每篇報告及綜合報告齊全且對應目前內容。
  3. 核心內容有獨立查核，發現的問題已修正或明示限制。

符合即交付完成，可含已知限制。漏讀、缺報告或缺獨立查核則是部分完成，仍交付現有報告與缺口。事件漏記不阻止輸出。未確認的內容不能以確定結論呈現。

維護與工具

沿用 Python 標準函式庫工具；新 schema v2／contract v3，歷史資料不遷移。工具處理來源雜湊、版本綁定與 Markdown，agent 負責實際閱讀和判斷。

  • 執行入口
  • 精簡 JSON 與命令
  • 實作計畫
  • 實測結果與限制

基本查核不保證沒有未知錯誤。實際速度以測試紀錄為準。

學術回顧與評析的平衡

預設約 60% 學術回顧、40% 證據與限制評析。先介紹研究動機、方法機制、核心貢獻及跨篇關係，再用中性語氣說明證據範圍與後續研究方向。比例是寫作重心，不是新增驗收門檻；必要數值釐清保留，詳細查核對照留在單篇及查核紀錄。

交接與速度優化

Reader／checker 各讀自己的短指引與範例。預設以 apply_patch 寫 UTF-8，避免 shell pipe 損壞文字。prepare PAPER --author CHECKER 一次產生單篇報告、查核綁定與原文交接包；交接包包含核心重點、原文摘錄、圖片路徑及章節／表格索引。prepare CHECK 只更新對應報告。第一篇完成即建立綜合初稿，隨查核結果更新。原文仍須完整閱讀，查核者仍須實際檢視必要圖片。

參考文獻

綜合報告文末固定列出 References／參考文獻，將每個 P001、P002 等論文 ID 對應至完整作者、原始題名及可確認的出版資訊。預設 APA 7，可依要求改用 IEEE。來源缺少年份時用 n.d.；不從檔名推定年份或猜測會議／期刊。引用已提供或確認的 DOI／網址，否則連結本次供應稿件。書目整理納入原有交付步驟，不另開查核流程。
